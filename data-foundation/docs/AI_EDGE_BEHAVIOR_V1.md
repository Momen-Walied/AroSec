# AI Edge Behavior Intelligence v1

Phase 1 of the Vigilance / AroSec AI roadmap. Built **above** the frozen
`CYBER_GRAPH_DATA_CONTRACT_V0.2`; it does not modify the Network → AI contract.

**Question answered:** *Given a communication relationship A → B and all history strictly
before time T, how unusual is the behavior of this relationship at T?*

> **Terminology.** This detects **behavioural anomalies in temporal communication
> relationships**. UNSW-IoTraffic has **no attack labels** and its identities are
> `dataset_ip_fallback` (source MACs are null) → results are **communication-entity /
> relationship anomalies**, *not* device anomalies. No claim of lateral-movement, malware,
> attribution, compromise, or attack-stage detection is made.

## 1. Pipeline

```
EdgeFeatureWindowV2 (frozen v0.2)
   → causal feature matrix (edge_features_v1)
   → {statistical | isolation forest | autoencoder}  (fit on TRAIN only)
   → validation-derived calibration (threshold + severity)
   → EdgeAnomalyResultV1 (score + severity + reasons + evidence)
```

Code: `ai/`. Nothing in `src/` (Data Foundation) was changed.

## 2. Input contract

`EdgeFeatureWindowV2` (real fields, used verbatim):
`connections_count, packet_count, outbound_bytes, inbound_bytes, protocol_distribution,
application_protocol_distribution, observed_destination_ports, observed_source_ports,
unique_destination_ports, unique_source_ports, relationship_age_seconds,
historical_connection_count, new_peer, src_unique_peer_count, src_new_peer_count,
protocol_novelty_count, protocol_novelty_ratio, port_novelty_count`.

## 3. Feature preparation (`edge_features_v1`)

Derived matrix (25 features), deterministic and versioned
(`ai/edge_behavior/features/builder.py`):

* volume: `log_connections, log_packets, log_out_bytes, log_in_bytes, out_in_ratio`
* ports: `log_unique_dst_ports, log_unique_src_ports, port_novelty_count, port_entropy,
  port_wellknown_fraction, port_privileged_fraction`
* network protocols: `n_protocols, protocol_entropy, dominant_protocol_share,
  protocol_novelty_count, protocol_novelty_ratio`
* application protocols: `n_app_protocols, app_protocol_entropy, app_protocol_novelty_count`
* peer/fan-out: `new_peer, log_src_unique_peers, log_src_new_peers, fan_out_ratio`
* age/history: `log_relationship_age, log_historical_conn`

**Port representation:** not one-hot encoded. Ports are summarised by count, novelty,
entropy, well-known-port fraction, and privileged-port fraction. **Transform:** `log1p` on
skewed counts/bytes; `RobustScaler` inside IForest/AE (fit on TRAIN only).
`app_protocol_novelty_count` is computed causally per relationship across windows.

## 5. Models

| model | type | notes |
|---|---|---|
| `edge-stat-v1` | robust per-feature z (median/MAD) → weighted components → [0,1] | interpretable reasons by construction |
| `edge-iforest-v1` | IsolationForest (200 trees) + RobustScaler, sigmoid-normalised | validation-calibrated |
| `edge-ae-v1` | compact MLP bottleneck `16-8-4-8-16`, reconstruction error | CPU-only |

## 12. Final decision report

1. **Best model overall.** The **validation-weighted fusion (statistical + isolation forest)**
   is best overall: it detects all novelty classes (NEW_PEER / FAN_OUT / COMPOUND = 1.00;
   NEW_PORT 0.54; NEW_PROTOCOL 0.65; VOLUME 0.60) at a controlled **1.84%** alert rate.
   The **statistical model is the best single model for pure novelty detection (0.97 mean)**
   but over-alerts under drift (9.68%); **isolation forest is the best-calibrated single model**
   (0.89%) but is nearly blind to single-feature port/protocol novelty.
2. **Does the autoencoder help?** **No.** It is the weakest (mean detection 0.64), overfits
   (train reconstruction ≈ 0), saturates, and is **excluded from the production fusion**. The
   simpler models are better — the deep model is not adopted.
3. **Practical threshold.** Fusion **0.315** → 1.84% of windows (~39 alerts/day). For a tighter
   budget, isolation forest **0.709** → 0.89% (~19 alerts/day). Severity is anchored to the
   operational alert-rate target, not hardcoded.
4. **Alerts per asset/day.** Fusion ≈ **5.6**; isolation forest ≈ **2.7**; statistical ≈ 29.6.
5. **Alerts per relationship/day.** Fusion ≈ **0.66**; isolation forest ≈ **0.32**.
6. **Reliably detected perturbations.** NEW_PEER, FAN_OUT_BURST, COMPOUND (100% for the
   statistical model and fusion).
7. **Difficult perturbations.** NEW_PORT and NEW_PROTOCOL (single-feature novelty): isolation
   forest 0.16 / 0.04; fusion improves to 0.54 / 0.65. TRAFFIC_VOLUME_SPIKE is moderate
   (statistical 0.81, fusion 0.60). Pure volume spikes are the hardest for a novelty-centric model.
8. **X-IIoTID sanity.** Yes — attack windows receive higher scores than benign (isolation
   forest ROC-AUC 0.704, PR-AUC 0.555; statistical 0.636). Positive but **not** validated detection.
9. **CPU edge suitable.** Yes. Sub-millisecond per-row inference, ≤8 MB artifacts, <13 MB peak
   memory, no GPU, no deep-learning runtime.
10. **Top contributing features.** `new_peer`, `src_new_peer_count`/`fan_out_ratio`
    (FAN_OUT_DEVIATION), `port_novelty_count`, `protocol_novelty_count`/`protocol_novelty_ratio`,
    `log_connections`/`log_out_bytes` (TRAFFIC_VOLUME_DEVIATION).
11. **Known limitations.** (a) UNSW identity is IP-derived — relationship/entity anomalies, not
    device anomalies. (b) No attack labels → evaluation is scenario-based + sanity only.
    (c) Temporal drift inflates the statistical model's alert rate on later periods; thresholds
    from validation do not transfer perfectly. (d) Single-feature novelty is hard for
    IForest/AE. (e) The autoencoder is not competitive. (f) Campaign/lateral-movement claims
    remain out of scope.
12. **Ready to integrate with Network v0.2 streams?** **Yes, for the contract and pipeline**
    (`EdgeFeatureWindowV2 → EdgeAnomalyResultV1`, versioned, deterministic, CPU-fast, with
    reasons and evidence refs). Recommended integration posture: deploy the **fusion** with
    drift monitoring and periodic re-calibration, and surface the **statistical model's reasons**
    as the analyst explanation layer. Identity must be presented as provisional for IP-only data.

**Scope discipline:** Node Behavior, Temporal GNN, Attack Path, and Campaign work are **not**
started; this phase must be reviewed first.
