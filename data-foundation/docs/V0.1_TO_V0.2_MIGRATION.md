# V0.1 → V0.2 Migration

v0.2 is **additive**. v0.1 schemas, tables, CLI commands, and the
`CommunicationEdge` interface remain available and unchanged for existing consumers.
v0.2 becomes the **authoritative** graph representation.

## 1. Why v0.2

The architecture review (`DATA_FOUNDATION_V0.1_ARCHITECTURE_REVIEW.md`) identified three blockers:

1. **Protocol/port loss** — v0.1 collapsed a window to `dst_port = min(...)` and
   `application_protocol = sorted(...)[0]`. A 19-port scan became one port.
2. **Relationship/observation conflation** — one table mixed a persistent edge with
   per-window observations.
3. **Identity correctness** — the resolver materialized roots during union (fragmentation),
   and used IP as a global join key (DHCP reuse risk).

## 2. What v0.2 adds / changes

| Area | v0.1 | v0.2 |
|---|---|---|
| Identity | `identity_method`, single-key, IP joins globally | + `identity_evidence`; **time-bounded** `AssetIdentifierObservation`; IP never a global join key; two-phase unions |
| Persistent edge | implicit (`edge_id` reused per window) | **`CommunicationRelationship`** (window-independent `relationship_id`) |
| Per-window fact | `CommunicationEdge` (lossy) | **`CommunicationObservation`** (lossless proto/app/src_port/dst_port) |
| Edge features | `EdgeFeatureWindow` (per pair/window) | **`EdgeFeatureWindowV2`** (per relationship/window) with `protocol_distribution`, `application_protocol_distribution`, `observed_destination_ports`, `observed_source_ports`, novelty counts/ratios |
| Events | ASSET/EDGE_* | + `IDENTITY_BINDING_ADDED/EXPIRED`, `RELATIONSHIP_ADDED/UPDATED`, `COMMUNICATION_OBSERVED` |
| Provenance | `evidence_sources` | + `evidence_id`, `source_record_id` (never fabricated) |

## 3. Identity method mapping

| v0.1 | v0.2 |
|---|---|
| `mac_pinned` | `mac_based` |
| `dataset_derived` (device name) | `dataset_device_id` |
| `hostname` | `dataset_device_id` |
| `ip_only` | `dataset_ip_fallback` (multi-observation) / `ip_only_observation` (single) |
| — | `multi_signal` (MAC + host/device) |
| — | `dhcp_mac_correlated` (MAC seen with ≥2 IPs over time) |
| `manual` / `unknown` | `manual_authoritative` / `unknown` |

Legacy members are retained in the enum so v0.1 tables still parse.

## 4. Consumer migration paths

* **Existing v0.1 consumers** — no change. `data/processed/**` (v0.1) and the
  `datasets normalize` / `build-graph` commands are untouched.
* **New AI/Graph consumers** — read `data/processed/v2/**` (assets, asset_identifiers,
  relationships, communication_observations, edge_features, graph_events).
* **Need the old table from v0.2 data?** Use the compatibility view:

  ```bash
  python -m src.cli export-v01 --dataset unsw_iotraffic --window 30s
  ```

  which reproduces the v0.1 `CommunicationEdge` interface (see `src/compat/v01.py`).

## 5. Lossiness of v0.1 (documented)

`CommunicationEdge` is **lossy for multi-protocol / multi-port pair-windows**:

* destination port = `min(observed)`;
* application protocol = lexicographically-first observed;
* one row per `(src, dst, network_protocol, window)`.

Measured on real data (v0.2 vs v0.1):

| dataset | ports lost under v0.1 | multi-protocol pair-windows |
|---|---:|---:|
| X-IIoTID (derivative) | **108** | 0.0% |
| UNSW-IoTraffic (sample) | **35** | 13.58% |

v0.1 remains usable but is **not** the authoritative graph representation.

## 6. What remains experimental / unvalidated

* **Campaign / provenance semantics** — unchanged; `observed_path`, `entry_asset_id`,
  `probable_target_asset_id`, `probable_objective` remain **unvalidated against real CICAPT
  data** and are never inferred. No material redesign until real files are ingested.
* **`EdgeFeatureWindowV2.protocol_novelty_ratio` denominator** = distinct protocols in the
  window; **`*_distribution` denominators** = `connections_count`. Frozen as documented, but
  the exact feature set may evolve.
* **UNSW identity** is `dataset_ip_fallback` (MACs are null) — do not treat UNSW node ids as
  device identities.

### Known identity limitations (v0.2.1 backlog)

* **IP-only reuse** — an IP that is *never* seen with a strong identifier (MAC/hostname/device)
  maps to a single `dataset_ip_fallback`/`ip_only_observation` asset per IP. Two unrelated
  devices that only ever appear IP-only on the same IP at disjoint times will therefore share
  one provisional asset. Flagged by low `identity_confidence`; consumers must not treat it as
  device identity.
* **Strong-component IP gap** — a strong component's IP binding uses one `(min,max)` interval,
  so an IP-only observation inside a quiet gap of that interval is attributed to that component.
  Distinct strong components sharing an IP are still kept separate (the core requirement).
  v0.2.1 will split bindings into contiguous sessions.

### `IDENTITY_BINDING_EXPIRED` semantics

Emitted **only** when the same identifier value is next bound to a **different** asset
(an identifier handover), at the later binding's `valid_from`. It is **not** emitted at
last-seen, so it never falsely implies expiry.

## 7. Rollback

v0.2 is written only under `data/processed/v2/`. Deleting that directory (or ignoring it)
reverts to a v0.1-only state with zero impact on v0.1 outputs.
